# BDFL Governance (Benevolent Dictator for a Set Period of Time)

The governance model for the Team Capabilities section, addressing the [[autonomy-factor-test|autonomy]] and org-maturation questions.

- Most successful FOSS projects run under a **Benevolent Dictator For Life** (BDFL — e.g. Torvalds/Linux). Good when an org is *young*; later, centralization becomes a risk and control should "melt into the community" (cf. Ton Roosendaal stepping down from Blender lead).
- The plan: **Benevolent Dictator for a Set Period of Time (BDfaSPoT).** Transition from centralized control: *President → President + Board → President + Board (C-Suite) + Community DAO.* President keeps ≥51% control until ~year 5, then an optional 50/50 President/Board+Community transition.
- **Public Requests-for-Comment** (like the Python PEP system) for planned features — transparency without a bottleneck.
- **Year 2:** a Developer Fund + Community Grants program; stakeholders vote (DAO-like).
- **Years 4–5:** extend the voting system to community steering of the org.

This is the deliberate [[conways-law|Inverse Conway Maneuver]] — structuring the org to produce the desired open, refactorable architecture — and it maps to the X-Labs "new organizational research structure" objective. `#design-lesson`
